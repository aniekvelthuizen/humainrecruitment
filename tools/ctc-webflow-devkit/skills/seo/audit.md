# The SEO checklist — what the audit measures and what to do in Webflow

The final audit (SKILL.md §7) goes through this list on the published site with [seo-audit.mjs](${CLAUDE_PLUGIN_ROOT}/references/fixture/seo-audit.mjs). Points 2, 4, 6 and 7 overlap with the [accessibility](../accessibility/SKILL.md) check, which owns those rules; the SEO audit measures them too so one run gives the whole list. Every fix happens where every page follows: the component, the CMS template, the page frame or the site settings — never page by page, and Lumos-proof (Element settings and Lumos classes, no custom CSS for structure). The script prints the matching fix under each finding; this table is the overview.

## What the script cannot judge

Mark these by hand in the report:

- **Whether an alt is good**: it flags missing alts and file names, not an alt that describes the wrong thing. Read the alts of the hero and the cards on two pages.
- **Whether a font is subset**: it reports file sizes (> 100 kB is suspect for one WOFF2 weight) and preloads; a 30 kB file can still hold every glyph of a Latin set, which is fine.
- **Captions inside a YouTube or Vimeo player**: it lists embedded players; check them in the player.
- **Structured data validity beyond the required fields**: run two pages per type through the Rich Results Test (https://search.google.com/test/rich-results) once the site is public.
- **robots.txt and canonical on production**: staging blocks all crawling and usually has no canonical. Run the audit once more on the production domain on launch day.
