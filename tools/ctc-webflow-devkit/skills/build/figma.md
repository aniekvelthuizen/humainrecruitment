# Source: Figma

Reading rules in [figma-reading.md](../../references/figma-reading.md). Tool calls in [figma-mcp.md](../../references/figma-mcp.md).

1. **Pick the source for this job.** A Figma URL in the request → MCP. Files already in `references/figma/<page>/` → files. Both, or neither → one question in the asking format, with `project.json`'s `figma.source` as the recommended answer.
2. **Dump.** MCP: `get_metadata` on the page, then per top-level frame `get_design_context` + `get_screenshot`, written to `references/figma/<page>/section-NN.md` and `section-NN.png`. Files: read what the user dropped there and write the same `section-NN.md` per section. Done when every section has a spec with full text and opacity.
3. **Index.** Per section, what the site already has: same component (`references/components.json`, then `query_components`), same block on another page (`query_elements` with a text filter on a distinctive sentence), same class names (`references/classes.txt`). A grep on the class list is not a reuse check; open the class and read its properties before borrowing it.
4. **Locate — prove the page before planning.** Find the Figma **page frame** that contains the section (walk up from the node in `get_metadata`) and match its name to a Webflow page in `references/pages.json`. A section that looks like it belongs on the page you are working on may sit in another page's frame; when the frame and the page the user named disagree, that is a plan question, not a guess. Then read the sections already built on that page, directly above and below the insertion point: two pages of the same site can use different section systems (borders, padding, eyebrow classes, variables vs literals), and the new section follows its neighbours on **its** page, not the last page you built on. Record page id, parent element and position (before/after which element, never "append" by default) in the plan. When the page does not exist, creating it is part of the plan.
   **Global blocks: find the real one.** A Figma component named `footer` (or `nav`) can be a wrapper that stacks call-to-action sections (about, contact form, scheduler) above the actual footer, with page instances showing different subsets — the instances then have very different heights. Open the component's children with `get_metadata`: the child that every instance ends with (here `footer-v2`) is the global component; the sections above it are page sections, built with their pages. Hidden variants in the set are alternatives, not states. Name this split in the plan.
5. **Missing.** Fonts not on the site, copy that says lorem, CMS collections not there: questions for the plan, asked once. Images and icons are not a question: `download_assets` from Figma, `asset_tool > upload_image_by_url` into Webflow, ids into the plan.

Then back to the plan step.
